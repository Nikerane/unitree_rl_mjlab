## What was implemented

Branch `codex/z1-impact-speed`, code baseline `3ca89a2`, implementation through `f7560d8` before the final docs/test correction. The separately registered `Unitree-Z1-Hammer-Quintic-M20-ImpactSpeed` extends the native Z1 quintic-M20 VIC policy with a thirteenth one-shot speed-selection output. The first six joint-target and next six stiffness outputs retain their old meanings; no controller-side speed planner, extra first-step hold, new dense velocity tracking, or change to existing task registrations was added. The goal is latched on the first policy action; its conditioning starts with the next decision. External-goal qualification mode uses the same controller with the goal supplied at reset and selector inactive. The event cost is one-shot, physically measured at first accepted contact, and remains separate from actual delivered impulse and soft-CaT pressure.

The experimental actor uses a recorded active-action mask in likelihood, entropy and KL; only the original 40 observation coordinates are normalized. Checkpoint identity `impact_speed_v1` checks action/observation order, bounds, mode, controller and safety configuration. PT stores the contract and mask-derived rollout summaries; it does not archive raw rollout tensors. A distinct qualification-to-autonomy transfer carries controller, critic and normalizers into a fresh runner/optimizer, zeros only the untrained selector output row/bias, and initializes its std. Normal resume is still strict. The evaluator supports external, autonomous, post-latch intervention, and zero-learning smoke modes, preserving terminal event/physical measurements before native auto-reset.

The four explicit design/execution rulings and their costs if wrong are:

1. Smoke may instantiate an **untrained** experimental actor without a checkpoint; all non-smoke modes require one. This resolves smoke-before-training against a blanket checkpoint requirement. Cost if wrong: smoke does not validate trained weights; separate checkpoint roundtrip tests do.
2. Keep the legacy `_NEG_TERMS` tuple unchanged and classify `speed_goal` through an explicit optional-negative extension. This preserves the frozen legacy FIC evaluator. Cost if wrong: the second classification path could diverge; tests cover old positives, new negative exclusion and unknown-negative rejection.
3. Preserve all three distribution tensors in rollout storage but persist schema plus mask-derived telemetry summaries in PT, **not** full raw rollout tensors. This follows the Task 5 contract and existing checkpoint-size behavior. Cost if wrong: a checkpoint alone cannot reconstruct raw rollout samples; a separate trace capture would be needed.
4. Use the approved focused acceptance suites and native gates for **software handoff only**, leaving the branch unmerged and the full historical suite explicitly incomplete. The optional sweep spent over nine minutes largely in unchanged campaign builders. Cost if wrong: regressions outside selected suites may remain; neither full-suite-green nor merge-ready is justified.
