# Native actuator saturation and substep oscillation: primary-source review

Date: 2026-09-22. Research/diagnosis only; no configuration changes or training.

## Finding

**Force saturation is a concrete candidate even with `implicitfast`, not evidence that the run must use Euler.** MuJoCo Warp **v3.8.1** computes the affine actuator force and then clips it to `actuator_forcerange`. Its velocity-derivative kernel explicitly sets the actuator derivative to zero when the already-computed actuator force is at either force bound. Thus, while saturated, the native servo's `kv` does not contribute its usual implicit damping derivative. This is intended handling of the locally flat clipped force law, not by itself a simulator bug. [Version-pinned force implementation](https://github.com/google-deepmind/mujoco_warp/blob/v3.8.1/mujoco_warp/_src/forward.py#L950-L970), [version-pinned derivative implementation](https://github.com/google-deepmind/mujoco_warp/blob/v3.8.1/mujoco_warp/_src/derivative.py#L65-L109).

For a unit-gear native position servo with no activation lag, the corresponding force is `clip(kp*(target-q) - kv*qvel, lo, hi)`. The reported joint-6 initial error, 0.0551646 rad, implies **44.13 Nm** from the proportional term at zero velocity, exceeding the reported 30 Nm bound. At 4.6 rad/s the damping term alone has magnitude approximately **411.4 Nm**. These are calculations from the supplied trace/configuration, not measurements of applied force. They make alternating saturation plausible, but do not establish the actual force signs, transmission, constraints, or effective inertia. [Position-actuator mapping](https://mujoco.readthedocs.io/en/3.8.0/XMLreference.html#actuator-position).

The reported reversal every 2 ms before contact, and postponement of the spike when the initial target is held for 20 ms, implicate the command transition and substep dynamics rather than a contact-triggered event. This is an inference, not a completed causal diagnosis. The parent investigation separately verified that installed mjlab defaults to `implicitfast` and hammer does not override it; a diagnostic should still print the compiled runtime option.

## Version and interpretation boundaries

- MuJoCo 3.8.0 documentation distinguishes actuator `kv` from passive damping: Euler does not integrate `kv` implicitly; `implicitfast`/`implicit` can. Actuator `kv` force is subject to actuator force limits. High gains alone therefore do not imply robust tracking under saturation. [Official XML reference](https://mujoco.readthedocs.io/en/3.8.0/XMLreference.html#actuator-general-damping).
- Warp v3.8.1 supports Euler, RK4, and **implicitfast**, not the full MuJoCo `IMPLICIT` integrator. Its function named `implicit()` is dispatched for `IMPLICITFAST`; the function name must not be mistaken for full-integrator support. [Tagged compatibility table](https://github.com/google-deepmind/mujoco_warp/blob/v3.8.1/README.md#supported-features), [step dispatch](https://github.com/google-deepmind/mujoco_warp/blob/v3.8.1/mujoco_warp/_src/forward.py#L1260-L1272).
- In this version, implicitfast is implicit **in velocity**, not a promise of unconditional stability for position stiffness or saturated servos. Smaller physics steps are an official stability/accuracy diagnostic; RK4 is not automatically superior for strong velocity-dependent forces. Do not import newer `latest` documentation's `discrete` integrator into a 3.8.1 recommendation. [Versioned numerical-integration documentation](https://mujoco.readthedocs.io/en/3.8.0/computation/#numerical-integration).
- Documentation cited above is explicitly 3.8.0 because the 3.8.1 documentation URLs were unavailable during this review; all Warp implementation claims are directly pinned to v3.8.1.

## Minimal causal tests, not fixes

1. **One frozen-state, deterministic replay:** capture compiled integrator, actual device timestep, gain/bias arrays, gear, force/control limits, initial q/qvel, and the exact submitted control target. At each physics step log pre-step target/error/qvel, raw affine actuator force, clipped `actuator_force`, mapped `qfrc_actuator`, relevant constraint/passive forces, and post-step qvel. Keep quantities phase-aligned: force buffers from a completed step may describe the pre-integration state. Confirm whether ±30 Nm alternation precedes and explains the velocity reversals. Do not infer applied torque solely from `kp*error`.
2. **Physics-step convergence:** replay the identical target schedule at 2, 1, and 0.5 ms while maintaining **20 ms control** (decimation 10, 20, 40), identical initial state and physical-time horizon. Freeze reference/IK outputs from the baseline so altered state feedback cannot change the experiment. Compare first-spike amplitude, time, sign-flip rate, saturation fraction, and q trajectories at common physical times. A two-step numerical oscillation that shrinks or changes frequency with timestep is discriminating evidence; different contact timing alone is not.
3. **Command-trigger isolation:** replay the observed jump versus the supplied initial-hold control, aligned to time since the first target change. Add a deliberately smaller first jump that stays inside the measured force bound at the same initial state, for a short pre-contact diagnostic only. If both saturation and the large alternating transient disappear, this supports saturation-triggered dynamics; it is not yet a task-level remedy.
4. **Only if needed:** match the same compiled model, initial state, control trace, and supported integrator in CPU MuJoCo and Warp. Agreement implicates the model/discretization rather than a Warp-only issue; disagreement requires verifying precision, model transfer, and stepping API before reporting a backend defect. An Euler-versus-implicitfast comparison is secondary and must not replace the saturation/timestep tests.

The timestep sweep is an **isolated diagnostic replay**, not checkpoint qualification: the native checkpoint contract requires 2 ms physics. Do not bypass that contract or describe altered-timestep results as qualifying the existing checkpoint.

Do not raise effort limits or armature, change gains or assets, smooth the production action path, or start training based on this source review alone. The immediate missing evidence is the time-aligned applied-force trace and fixed-control-period timestep convergence.
